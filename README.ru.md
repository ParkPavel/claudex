Клаудекс — небольшой локальный харнесс для разработки реального продукта с двумя
ИИ-провайдерами. Он держит поддерживаемые инструкции в одном месте, выдаёт каждому заданию явную
роль и закреплённый снимок исходников и отделяет «готово» модели от проверенной приёмки.

> **Главная идея.** Готовность решают улики, привязанные к тому самому состоянию, на котором
> их сняли, — дайджестам исходников, конфигурации и спецификации, — а сделанное одной моделью
> проверяет другая. Всё, что не показано, остаётся `UNKNOWN` и никогда не становится `PASS`
> по умолчанию.

## Быстрый старт

*Начинаете новое? Сразу в [Borshkit](https://github.com/ParkPavel/borshkit) — всё ниже
сохранено для существующих установок.*

Нужны Node.js 22+, Git и авторизованные CLI Claude Code и Codex. Управляемый проект — отдельный
Git-репозиторий рядом с `claudex/`.

```sh
git clone https://github.com/ParkPavel/claudex.git
cd claudex
node bin/claudex.mjs setup --workspace ..
```

Окно установки ничего не записывает, пока вы не подтвердите сводку. По порядку оно:

1. **показывает окружение** — node, git, оба CLI провайдеров, — чтобы недостающий инструмент
   нашёлся сразу, а не на первом упавшем задании;
2. спрашивает **управляемый проект** и перечисляет, что появится рядом с ним;
3. предлагает **профиль**, на который проект похож (манифест Obsidian → `obsidian`);
4. спрашивает, **что писателю можно без спроса** (`full`, `scoped`, `approval`);
5. спрашивает, **какая модель отвечает за какую роль**, — по строке на роль;
6. записывает **рабочие принципы**: язык ответов, защищённую ветку, кто делает merge, какие
   проверки обязательны перед «готово», — чтобы ни один агент не пересказывал ваше согласие
   с чужих слов;
7. предлагает поставить **хуки Claude Code** и в конце запускает `doctor`.

Запустите окно снова, чтобы изменить любой ответ. В скрипте те же решения принимает `init`
флагами. Архив выпуска ставится распаковкой и запуском `setup.cmd` (Windows) или `setup.sh`
(Linux/macOS).

## Как проходит задача

```text
 task init ──► task check ──► worktree + approve ──► run (implementer) ──► task verify
  контракт      предупреждения   отдельный чекаут       пишет в свою           проверки привязаны
                                                         ветку                  к снимку
                                                                                     │
 task converge ◄── wait / отчёт ◄── run (auditor, другой провайдер, только чтение) ◄─┘
  PASS · FAIL · UNKNOWN по каждому критерию
```

| Шаг | Команда | Что гарантирует |
|---|---|---|
| Контракт | `task init <id>` → правка → `task check <id>` | Цель, не-цели, решения, пути, критерии, проверки. `check` ещё и **предупреждает**: критерий, который не покажет ни одна проверка, заглушки, код без typecheck или линтера, проверки, которых требуют ваши принципы |
| Изоляция | `worktree <id> --paths src/lib` | У писателя свой чекаут и занятые файлы; пересечение — только с записанной причиной |
| Задание | `run packet.json` | Фоновый работник, точный ID, закреплённый снимок, провайдер и модель по роли |
| Улики | `task verify <id> --check <check>` | Лог проверки и дайджесты сохраняются; последующая правка делает их `STALE` |
| Ревью | `run review.json` | Ревьюер другого провайдера только читает и получает проверки, уже прогнанные на его снимке |
| Ожидание | `wait [job] --timeout-min 40` | Ждёт завершения и печатает вердикты, пропуски и postmortem |
| Вердикт | `task converge <id>` | `PASS`, `FAIL` или `UNKNOWN` по каждому критерию, нарушения области, происхождение |

## Профили

Профиль несёт проверки и рабочие инструкции для одного вида проектов.

| Профиль | Обязательные файлы | `check-project` запускает | Живые улики |
|---|---|---|---|
| `generic` | — | по умолчанию ничего; проверки вашего контракта | — |
| `obsidian` | `manifest.json`, `package.json` | изолированный `npm run build`, `npm test` (JSON-отчёт), `npm run lint` | Obsidian CLI в объявленном **тестовом** хранилище; рабочие хранилища только для чтения |

Инварианты конкретного проекта живут в локальном `.local/claudex/project-profile.md` вместе с
рабочими принципами, которые записало окно установки.

## Отчёты

| Отчёт | Команда | Отвечает на вопрос |
|---|---|---|
| Сводка заданий | `status --summary` | Что идёт, что закончилось, где postmortem |
| Вердикты по завершении | `wait [job …]` | Критерии, находки, неотвеченные критерии (`resultGaps`), остановка |
| Postmortem | `artifacts/<job>/postmortem.json` | Что задание обещало, где остановилось, собственная ошибка провайдера, остатки, что проверить |
| Ретроспектива | `retro [--since ДАТА]` | Причины сбоев, задания по моделям, стоимость и токены, доля `UNKNOWN`, самые долгие прогоны |
| Здоровье каталога | `doctor` | Точки входа, провайдеры, деревья, заявки, передачи, разрешения, осиротевшие задания |
| Передача провайдера | `modes --status` / `--debt` | Кто за кого отвечает и какие перепроверки должны |
| Передача сессии | хуки | Состояние проекта на старте сессии, строка на каждую остановку, готовые отчёты — в следующий ход |

## Навыки и справочная библиотека

Навыки — короткие поддерживаемые инструкции; сгенерированные заглушки в `.claude/skills` и
`.agents/skills` указывают на них.

| Навык | Для чего |
|---|---|
| `spec-workflow` | привязать фичу или исправление к контракту и текущим уликам |
| `task-contract` | передать ограниченный вопрос другому агенту |
| `systematic-diagnosis` | найти причину до правки кода; прочитать причину падения каждого набора |
| `evidence-gate` | оценить заявление о готовности по уликам |
| `flow-render` | проследить действие пользователя от видимого обещания до сохранённого результата |
| `obsidian-acceptance` | спланировать живые проверки через Obsidian CLI |
| `native-ui-quality` | держать интерфейс на планке качества iOS, включая мобильный Obsidian |

`library/` — локальная справочная библиотека готовых решений: навыки дизайн-инжиниринга Эмиля
Ковальски и выжимка Apple Human Interface Guidelines. Их читают по необходимости через
`native-ui-quality`, никогда не вставляя целиком. Происхождение и лицензии —
[library/README.md](library/README.md).

## Безопасность

- **Ничего локального не публикуется.** Конфигурация, задания, улики, разрешения и резервные
  копии лежат в `.local/` рабочего каталога, вне этого репозитория. Учётные данные остаются в CLI
  провайдеров.
- **Полномочия заданы структурой.** Codex работает в песочнице только для чтения; управляемый
  писатель Claude получает ограниченные файловые инструменты без оболочки; писателю нужно своё
  дерево в своей ветке.
- **Публикация под охраной.** `scan` ищет секреты в индексе и истории; ограждение пуша отклоняет
  защищённые ссылки, force-push и удаления и записывает каждый пуш в журнал.
- **Хуки без оболочки.** Установленные хуки запускаются в exec-форме: путь никогда не станет
  командой.

Полная [модель угроз](SECURITY.md).
