# Клаудекс

Клаудекс — общее ядро для совместной работы Claude Code и Codex. Настройки поддерживаются
в отдельном публичном репозитории; управляемый проект, тестовый vault и личные данные
располагаются рядом с ним в локальном рабочем каталоге.

## Как устроен рабочий стол

В корне находятся `claudex/`, папка управляемого проекта и локальные области `.local/` и
`.tmp/`. Короткие `AGENTS.md`, `CLAUDE.md` и нативные определения ролей направляют модели
к общему контракту. Основные инструкции и навыки живут в `claudex/`; учётные данные туда
не копируются. Подробная [схема каталогов](README.md#workspace-layout).

## Начало работы

Нужны Node.js 22+, Git и авторизованные CLI Claude Code и Codex. Клонируйте репозиторий
рядом с уже существующим Git-проектом, выполните `npm install` внутри `claudex`, затем:

```sh
node bin/claudex.mjs init --workspace .. --project your-project --profile obsidian --vault "Test Vault"
node bin/claudex.mjs doctor --workspace ..
```

В `.local/claudex/workspace.json` укажите модель Codex, точный путь к тестовому vault и
`testVault: true`. Авторизация остаётся в штатных клиентах. Инструкция подключения —
[Obsidian CLI](docs/how-to/obsidian.md).

## Принципы работы

Один координатор управляет задачей. Он передаёт исполнителю цель, границы, принятые решения,
версию кода и проверяемые критерии. Реализация и независимое ревью — разные задания.
Исполнитель пишет в отдельный worktree; рецензент не может получить права записи.

Журнал различает запуск, готовность, выполнение и завершение. Ответ модели с PASS остаётся
предложением. Приёмка требует независимой проверки: видимый экран, успешная команда и
сохранённое состояние доказывают разные вещи. После изменения кода прежние свидетельства
нельзя незаметно применять к новой версии.

Включены пять небольших навыков: контракт задачи, диагностика причины, проверка свидетельств,
сопоставление обещания интерфейса с эффектом и приёмка в Obsidian. Основания и ограничения
методик приведены в [реестре источников](docs/research/evidence-register.md).

## Публикация и развитие

Публикуется только папка репозитория Claudex. Локальные настройки, vault, история диалогов,
резервные копии и результаты запусков остаются на машине. Git hooks проверяют индекс и
историю, блокируют удаление удалённых ссылок, небыстрые обновления и прямой push в защищённые
ветки. Серверные правила GitHub включаются отдельно: локальный hook можно обойти.
